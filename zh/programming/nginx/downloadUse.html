配置文件结构 ​

Nginx 配置由指令组成：普通指令以分号 ; 结尾，块指令用花括号 {} 包含子配置。指令只能放在允许它的上下文中，例如 worker_processes 位于主上下文，server 位于 http 上下文，location 位于 server 内。

常见结构如下：

nginx
# 主上下文
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;

    # 一个 HTTP 虚拟主机
    server {
        listen 80;
        server_name example.com;

        location / {
            root  html;
            index index.html;
        }
    }
}

常见主配置文件位置：Linux 包安装通常是 /etc/nginx/nginx.conf；Windows 通常是安装目录下的 conf/nginx.conf。实际路径可用 nginx -V 查看编译参数，或用 nginx -T 查看 Nginx 加载的配置。

常见上下文和指令 ​

上下文用途常见配置
主上下文全局进程和运行参数user、worker_processes、error_log、pid
events连接处理参数worker_connections
httpHTTP 服务的通用设置include、log_format、access_log、sendfile、gzip、upstream
server一个虚拟主机，按监听地址和主机名匹配listen、server_name、root、index
location按请求 URI 选择处理规则root、try_files、proxy_pass、return

include 用于引入其他配置文件，常见写法是 include /etc/nginx/conf.d/*.conf;。相对路径通常以 Nginx 的安装前缀为基准。修改配置后先运行 nginx -t 检查，再用 nginx -s reload 平滑重载。

静态网站示例 ​

nginx
server {
    listen 80;
    server_name example.com www.example.com;

    # 网站文件目录
    root /var/www/example;
    index index.html index.htm;

    # 先查找文件，再查找目录；均不存在时返回 404
    location / {
        try_files $uri $uri/ =404;
    }

    # 明确禁止访问隐藏文件（例如 .env）
    location ~ /\. {
        deny all;
    }
}

Windows 示例的 root 可写成 root C:/www/example;。请将域名和目录替换为自己的实际值，并确保运行 Nginx 的用户能够读取网站文件。

完整站点配置 Demo ​

下面是一份单页前端网站加 API 反向代理的示例。可保存为 conf.d/demo.conf，或合并到主配置文件的 http 块中（示例里的 server 块必须位于 http 内）：

nginx
upstream demo_api {
    server 127.0.0.1:3000;
}

server {
    listen 80;
    server_name demo.example.com;

    # 前端打包生成的文件目录
    root /var/www/demo/dist;
    index index.html;

    # API 请求转发到后端；尾部 / 会去掉 /api/ 前缀
    location /api/ {
        proxy_pass http://demo_api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 前端路由由单页应用处理
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 隐藏文件不允许通过 Web 访问
    location ~ /\. {
        deny all;
    }
}

将 demo.example.com、/var/www/demo/dist 和后端地址改成自己的域名、前端目录及服务地址。upstream 和 server 都需要放在 http 上下文中；如果使用 conf.d/*.conf，先确认主配置文件在 http 块内包含了该目录。

配置完成后检查并重载：

bash
nginx -t
nginx -s reload

location / 请求处理 Demo ​

location / 是普通前缀匹配，会接收没有被其他更具体规则处理的 URI。搭配 root 时，Nginx 把请求 URI 拼到网站目录后查找文件。以上面的配置为例：

请求Nginx 的处理结果
/查找目录 /var/www/demo/dist/，并使用 index.html返回首页
/assets/app.js查找 /var/www/demo/dist/assets/app.js文件存在则返回文件
/orders/42找不到对应文件或目录后回退到 /index.html前端路由接管页面
/api/users命中更具体的 location /api/转发到后端的 /users

如果是普通静态网站，不需要前端路由回退，可将 try_files 改成：

nginx
location / {
    try_files $uri $uri/ =404;
}

这样请求的文件或目录不存在时会返回 404，而不是返回单页应用首页。注意，location / 不代表只匹配根路径 /；如果只处理根路径本身，可以使用精确匹配 location = /。

反向代理示例 ​

以下示例把 /api/ 请求转发到本机 3000 端口的应用：

nginx
server {
    listen 80;
    server_name example.com;

    location /api/ {
        # 末尾的 / 会影响转发给上游的 URI
        proxy_pass http://127.0.0.1:3000/;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

例如请求 /api/users 时，上述带尾斜杠的 proxy_pass 通常会将 / 前缀替换为 /，上游收到 /users。如果写为 proxy_pass http://127.0.0.1:3000;（不带尾斜杠），通常会把原 URI /api/users 一并转发。涉及正则 location 或 URI 重写时规则更复杂，应按官方 proxy_pass 文档确认。

多个上游和负载均衡 ​

将 upstream 定义在 http 块中，再在 proxy_pass 中引用组名：

nginx
http {
    upstream app_servers {
        server 127.0.0.1:3001;
        server 127.0.0.1:3002;
    }

    server {
        listen 80;
        server_name example.com;

        location / {
            proxy_pass http://app_servers;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
}

默认按轮询方式分配请求；也可在 upstream 中设置 least_conn;，优先选择活动连接较少的服务器。每个 server 条目可用 weight=数字 调整权重。

配置匹配要点 ​

  • 同一地址和端口上可配置多个 server，Nginx 根据请求的 Host 与 server_name 选择虚拟主机；未匹配时使用该监听端口的默认服务器。
  • location = /path 是精确匹配；location ^~ /assets/ 优先处理指定前缀且不再尝试正则；普通前缀匹配会与正则 location 按 Nginx 的匹配规则共同判断。
  • root 会把完整 URI 拼到目录后面。例如 root /data; 配合 /img/a.png 对应 /data/img/a.png。
  • alias 用指定目录替换匹配到的 location 前缀，常用于单独映射目录；使用时需留意 location 和 alias 的斜杠对应关系。
  • index 指定访问目录时默认返回的文件；try_files 可按顺序检查文件或目录是否存在。
  • 大多数指令可在父级上下文设置并由子级继承，但各指令的继承规则不同；不要假定所有配置都会自动继承。

配置示例用于说明常见写法，部署前应替换域名、路径和上游地址，并根据实际环境设置 HTTPS、访问控制和日志策略。配置是否有效以 nginx -t 的检查结果为准。
