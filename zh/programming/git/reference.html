常用命令 ​

下面的 分支名、远程名、提交号 等是需要替换的占位内容。默认远程仓库通常叫 origin。

查看状态和改动 ​

bash
# 查看工作区、暂存区和当前分支状态
git status

# 查看尚未暂存的改动
git diff

# 查看已经暂存、即将提交的改动
git diff --staged

# 查看提交记录（单行显示）
git log --oneline

提交代码 ​

bash
# 暂存指定文件；用 . 暂存当前目录下的所有改动
git add 文件名
git add .

# 提交暂存区内容
git commit -m "提交说明"

# 推送当前分支（首次推送时建立上游关联）
git push
git push -u origin 分支名

获取和同步远程代码 ​

bash
# 克隆仓库
git clone 仓库地址

# 克隆指定分支
git clone -b 分支名 仓库地址

# 获取远程更新，但不合并到当前分支
git fetch

# 拉取并合并当前分支对应的远程更新
git pull

# 查看远程仓库地址
git remote -v

分支管理 ​

bash
# 列出本地分支；加 -a 可同时查看远程分支
git branch
git branch -a

# 创建并切换到新分支
git switch -c 分支名

# 切换到已有分支
git switch 分支名

# 删除已合并的本地分支
git branch -d 分支名

# 删除远程分支
git push origin --delete 分支名

暂存未完成的改动 ​

bash
# 暂存当前改动
git stash

# 查看暂存列表
git stash list

# 恢复最近一次暂存，并从列表中移除
git stash pop

# 恢复指定暂存（例如 stash@{0}）但保留在列表中
git stash apply stash@{0}

撤销改动 ​

bash
# 从暂存区移出文件，保留工作区改动
git restore --staged 文件名

# 丢弃文件在工作区的未提交改动（操作不可轻易恢复）
git restore 文件名

# 用新提交撤销某个提交，适合已经推送或多人共享的分支
git revert 提交号

git restore 文件名 会丢弃该文件尚未提交的内容；执行前先用 git diff 确认。git reset --hard 会直接重置暂存区和工作区，可能永久丢失未提交改动，使用前务必确认目标提交并备份需要保留的内容。

处理合并冲突 ​

执行 git pull、git merge 或 git rebase 时，如果双方改动了同一处内容，Git 可能会暂停并报告冲突。先查看冲突文件：

bash
git status

打开冲突文件后，会看到类似标记：

text
&lt;&lt;&lt;&lt;&lt;&lt;&lt; HEAD
当前分支的内容
&#61;&#61;&#61;&#61;&#61;&#61;&#61;
合入分支的内容
&gt;&gt;&gt;&gt;&gt;&gt;&gt; 分支名或提交号

编辑文件，保留需要的内容并删除 <<<<<<<、=======、>>>>>>> 这些标记。处理完所有冲突后，按当前操作类型继续：

bash
# 将已解决的文件标记为解决
git add 文件名

# 如果正在进行 merge，完成合并提交
git commit

# 如果正在进行 rebase，继续变基
git rebase --continue

如果想放弃当前操作，可使用对应命令恢复到操作开始前的状态：

bash
git merge --abort
git rebase --abort

解决冲突后应检查文件内容，确认冲突标记已全部移除，再提交或继续变基。git rebase --continue 可能因后续提交再次遇到冲突，需要重复处理；不要在不清楚影响时对共享分支执行变基。
